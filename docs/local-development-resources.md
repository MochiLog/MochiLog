# このMacでの開発リソース管理

このMacは16 GB RAMで、SSDの空きも限られる。ビルドを開始する前後に`df -h /`、`memory_pressure`、`sysctl vm.swapusage`を確認する。スワップが残っていることだけで不足の原因とは断定せず、作業中の増加とメモリプレッシャーを見る。

- 署名・公証・全言語UIテストなど重い処理はGitHub Actionsで実施する。
- ローカルのXcodeビルドは`-jobs 1`、Rustは`CARGO_BUILD_JOBS=1`。複数リポジトリのビルドとシミュレータを同時に動かさない。
- 必要なシミュレータだけ1台ずつ起動し、確認後は停止する。撮影用の不要な端末は削除して再作成する。ユーザーの個人用シミュレータには触れない。
- ディスク空きが12 GBを下回る場合は、重いローカルビルド・撮影を始めず、作業用キャッシュを整理するかCIへ移す。
- RAMのプレッシャーが上がる、スワップが継続して増える場合は処理を増やさず、起動したシミュレータと自分の不要な作業プロセスを停止する。
- 整理は自分が生成したDerivedData、一時アーカイブ、検証用展開ファイルに限る。アプリの記録、保管庫、ペアリング情報、ユーザーのアプリやデータを削除しない。

UIランナーには起動・実行の上限時間を設け、失敗後も自身のシミュレータを削除する。診断用ログは小さいテキストを残し、大きい一時成果物は検証後に整理する。
