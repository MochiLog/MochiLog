# PC連携の回復処理と権限案内（2026-11-18）

## 調査範囲

Mac / Windows 1.0.2の最新ネイティブ診断を直接取得し、スマホ側の共通受信処理と照合した。外出・ロック・古いIPによる接続不能だけをアプリ不具合とは認定しない。5分の収集周期と当日分取得後の節電休止は変更していない。

## 修正

- 応答の長さが揃ってもTCPのEOFを待ち続けていた。4バイトの長さヘッダーで完了を判定し、その後、既存のAES-GCM・要求nonce・ペアリング鍵による認証を通す。フレーム完了だけで受領・取り込みを確定しない。
- 宣言サイズの超過・ゼロ長・同一フレーム内の余分なデータを拒否する。上限超過時にも接続参照・期限・受信バッファを解放して次の経路へ進む。途中切断・不完全応答は成功にしない。
- Bonjourの順序・インターフェイス更新で接続準備をキャンセルし、試行中の経路番号をリセットしていた。進行中は既存の順序を保ち、新しい候補だけを追加する。候補は16件まで。検索が失敗しても利用中の直接接続を維持する。
- 経路が一つも見つからないと、複数PCの次の相手へ進まない。検索を8秒で区切り、既存の再試行処理で次のPCへ進む。
- 取消後の古いready通知から要求を送らないよう、送信前の所有者確認をMainActor上にまとめた。
- 認証に失敗した暗号化応答を「保存できない」と分類していた。認証エラーと保存エラーを分け、改ざん応答を拒否した後にも別PCへ回復できるよう確認した。

Mac・Windowsの両方に接続する共通クライアントの修正で、ワイヤー形式、鍵、受領ACK、重複照会、保存形式、ペアリング方式は変更していない。再ペアリング・マイグレーションは不要。

## ペアリングの権限

iPhone / iPadにはローカルネットワークの拒否、カメラの拒否、カメラの利用制限を分けて表示し、適切な場合だけ「設定を開く」を出す。QRスキャン前にカメラ権限を確認する。Macにもローカルネットワークの確認・警告・システム設定への入口を追加した。案内は8言語。

[Apple TN3179](https://developer.apple.com/documentation/technotes/tn3179-understanding-local-network-privacy)に従い、一般的な権限問い合わせAPIやTCCデータベースの直接参照は使わない。BonjourのDNS PolicyDenied (-65570) と接続経路のlocalNetworkDeniedを記録し、一般のタイムアウト・VPN制限・経路のsatisfiedを「ローカルネットワーク許可済み／拒否」と断定しない。以前のプロセスの観測も現在の拒否には使わない。

明示的な確認は8秒の期限を設け、画面を閉じたときやバックグラウンドへ移ったときにも停止する。設定から戻った際に既知の拒否を再確認する。警告によって利用可能なTailscale経路を一律に禁止しない。サポート情報を書き出すためだけに権限ダイアログを出さない。

## 検証

- `scripts/test-pairing-support.sh`: 断片化した3MiBの暗号化応答、EOFなしの完了、ヘッダー上限、末尾の余分なバイト、改ざん拒否、1000回の候補順変更、候補増加の上限を確認。期限、QR交換、権限観測、サポートZIPの既存試験も成功。
- 実際のMacTransferManagerを使うシミュレーター検証: EOFを送らない相手、不正サイズ、途中切断、改ざん応答、不在の先頭PCの5ケースをiPhoneとiPadで実行。合計10ケースで正常な相手への回復を確認。
- 修正前の233744dに同じDEBUG専用の試験入口だけを追加した隔離ビルドでは、EOF待ちと不在PCのケースが25秒後も未完了だった。最終版ではそれぞれ約1.8〜2.8秒、約14.8〜15.2秒で完了した。実回線の性能値ではない。
- 権限UI: ローカルネットワーク拒否を8言語、カメラ拒否・利用制限を英語と日本語で、iPhone / iPad各12ケース、合計24画面を検証。スクリーンショットで折り返しとiPadの右ペインを確認。
- シミュレーターはローカルネットワークプライバシーを実装しないため、上記UI検証では拒否観測を注入した。実機のOSダイアログの拒否・再許可を確認した証拠ではない。試験入口はDEBUGかつシミュレーターに限定し、Releaseでは除外する。

再実行する場合は、Debugビルドと`MochiLog Stability `から始まる名前の使い捨てシミュレーターで、`scripts/test-pc-transfer-stability-simulator.py`を使う。試験用Python環境のcryptographyを使うが、配布アプリへの追加依存ではない。GitHub ActionsのAutomatic collection UI verificationには`pairing_permissions`の専用実行を追加した。
