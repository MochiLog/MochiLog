# iCloud同期を利用する端末間のPCログ共有

2026-10-08。開発ブランチのベータ機能。LocalDevVPN方式の調査結果は `localdev-vpn-diagnostics-research.md` に分けて記録済みで、本機能へ診断取得ルートを混ぜていない。

## 利用者向け

同じPCとMochiLogペアリング済みのiPhone・iPadについて、同じApple Accountで双方のiCloud同期がオンと確認できた場合だけ、他の端末の解析ログも暗号化して受信できる。3台・4台でも同じ条件を受信先ごとに確認する。片方がオフ、別のアカウント、旧版・未確認なら共有しない。自分の端末のログは従来どおり受信できる。受信したログは元の端末の個体IDを保持し、受信先の履歴として混ぜない。

スマホアプリを開いている間に許可を再確認する。共有元をしばらく開いていない場合は共有を保留し、次に開いた際に再確認する。PC側が削除済みのログは復元しない。転送後の即時削除／保管、期間・容量設定は維持する。PC同士は同期しない。

## プロトコルとプライバシー

- 設定オンかつCloudKitアカウント利用可能時、同じコンテナの `userRecordID.recordName` にアプリ固有の名前空間を加えSHA-256を計算する。Apple ID・メール・元のrecordNameはPCへ送らない。ハッシュは同じアカウントの照合に用いる識別情報であり、匿名化の保証ではない。
- `cloudSharingVersion=1` / `cloudSharingScope` は既存v3 AES-GCMリクエストの暗号化・認証対象に含める。v2や未対応クライアントは許可を与えない。応答と事前照会も既存のnonce-bound暗号化を維持する。
- 許可はPCのメモリ内のみ・15分の期限。アプリが前面にある間だけ5分間隔の小さなpolicy-only要求で更新する。この要求は日次ログ取得・ACK・解析・診断保存・日次停止条件を変更しない。端末の同期オフ／アカウント変更は直ちに撤回要求を送る。通信できない場合は期限切れまでPCが直前の状態しか知れないという制約がある。アプリを閉じたままの設定確認・無期限許可は行わない。
- `Shared::<scope>::<元端末UUID>::<Host/Watchの既存token>` は各要素を厳密に検証する。任意パスの解決は禁止。各要求時、送信元が現在もペアリング済み、双方の有効なscope一致を再確認する。受信後／解析前／手動確認の保存直前にも受信側の許可を確認する。
- PC再起動後は許可を再取得する。古いスマホ・PCは元のペアリングのまま自分のログだけを扱い、新機能を推測で有効にしない。CloudKitのDevelopmentとProductionなどでuserRecordIDが一致しなければ安全側に保留する。

## 所有者と重複

- Hostログは元端末UUID、Watchログは元iPhone UUIDとProxiedDeviceを使う既存の別UUID。WatchログはiPhoneのProxiedDeviceから取得し、ヘッダーのWatch OSで分類する。
- 外部端末のACK／事前照会のhaveは受信先ごとの台帳だけ更新する。元端末のキュー、Delivered、当日完了記録を更新・削除しない。保管済みログも対象にできるが、未転送分を元端末への配信前に消さない。
- 受信台帳は元端末とSHA-256で確認し、別PCの受信待ちファイルも確認する。新しい自動PC取込のレコードIDは元個体IDと原本SHA-256から決定する。同じログを複数端末が同時に解析しても論理IDは同じ。
- CloudKitの一意制約へ依存しない。SwiftDataに同じ決定ID・元個体ID・ログ日時の複数コピーが届いた場合、永続化されたcreatedAtの最小値を全端末共通の保持基準とする。より新しいコピーだけ整理し、同じ最小時刻のコピーは残す。ローカルobjectIDや受信順で残す行を変えないので、A/Bが別の最後の1行を消す競合を避ける。保存失敗時はロールバック。旧ランダムID記録にはこの自動整理を適用しない。
- 表示／エクスポートでは同じ論理IDを1件として扱う。Mac上のiOS版は表示をまとめるだけで、共有許可の送信・取込・自動整理を実行しない。既存の3.2.2にも従来の記録形式で同期する。整理前に旧版がコピーを一時表示する可能性はあり、旧版自体に新しい収束処理を追加したわけではない。
- 別iPhoneの未知のWatchログを受信先の唯一の登録済みWatchへ自動割当しない。元個体IDの既存記録があればモデルを利用し、なければ既存の手動選択で確認する。

## 検証

Mac/Windowsの実際の暗号化ソケット試験で、4端末、未確認送信元、別アカウント、双方のoff、期限切れ、ペアリング削除、提示後の許可撤回、受信先ごとのACKとhave、原本保護を確認する。スマホのSwift試験ではtokenとパス拒否、Watchの個体分離、安定ID、逆順受信・部分同期・createdAt同値でも保持するコピーが消えないことを確認する。実装のCloudKitスキーマ変更はない。

## 追跡・並列処理

共有の送信元・受信先・許可理由・事前照会・ACK・解析結果を記録し、CloudKitの照合ハッシュと秘密鍵は残さない。転送nonceと段階ごとの経過msで遅延を追跡する。日次ログ収集と現在値取得は独立して並列動作する。当日の調査と詳細は `transfer-delay-2026-10-08.md` を参照。
