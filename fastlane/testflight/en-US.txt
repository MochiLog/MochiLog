New in 4.0.0 (1039): encrypted cross-device log sharing. Devices paired with the same computer can receive each other’s logs only when BOTH have iCloud sync enabled and the same Apple Account is confirmed. This applies per recipient with 3–4 devices too. Sync off, different accounts or unconfirmed settings prevent sharing; a source app not opened recently must confirm again. Source and Watch identities remain intact. Duplicate transfers/records are avoided, and another recipient’s ACK never consumes the source’s pending queue. Existing pairings and own-device transfers remain compatible with earlier versions.

Daily-log collection and current battery acquisition now run independently in parallel on Mac/Windows. Dated diagnostics trace jobs, preflight, response preparation/write, application ACK, parsing times, sharing reasons and source/recipient IDs. Secret keys, account-matching scopes and battery values themselves are excluded. Windows permits slow transfers beyond 25 seconds overall while timing out stalled communication. Requires Mac 0.2.19 Beta / Windows 0.1.16 Alpha for sharing. No PC-to-PC sync or recovery of deleted raw logs. If revocation cannot reach a computer, its last consent expires within 15 minutes.

Live Battery is OFF by default in Advanced Settings. It has a separate tab on mobile and desktop; Overview starts with paired devices. Mobile shows friendly model names, combines identical readings from multiple PCs and compares differences, retaining each acquisition time/state. The table uses verified paths for cycle count, root design capacity, charging, power, voltage/current. Missing root design capacity is unavailable. Uncertain capacities, charge levels, nested fields, codes and channels stay in optional collapsed details, with exact precision and no guessed units. Channel names are not temperature readings.

Values refresh while open; only changes are encrypted and sent. Receive Now, Send Now and remote refresh are available. Current values stay in memory, never history, records, iCloud or diagnostic logs. Missing/outdated values are distinguished. The maintained pymobiledevice3 diagnostics API varies by device/OS/connectivity. A locked query succeeded, but this does not guarantee all locked queries or locked daily-log collection. Live Watch values are not included.

Companion beta: iOS/iPadOS 27, macOS 27, Windows 11. Windows initial USB trust needs Apple Devices or classic iTunes EXE from Apple. Trust once over USB, then scan the PC QR in Settings → Advanced Settings → PC Transfer; existing wireless OS pairing can skip USB. Manual mobile import still works without a PC.

Daily Analytics collection needs an unlocked device, including Watch files stored on iPhone. Parsing/recording remain on mobile. Multiple PCs use authenticated duplicate inventory and confirmation on both sides. Automatic communication pauses after required daily logs complete, except consent checks for cross-device sharing. Tailscale with cellular permission enables receipt away from home. Storage can delete delivered files immediately or retain them, with adjustable 500 MB/one-month defaults; unreceived files stay protected.

View/copy diagnostics by date. Support can attach both sides’ incident-day and two preceding days’ logs. Exact duplicate records can be reviewed after backup. iPad settings remain in the right pane; PC transfer is hidden on mobile-on-Mac.

Prior fixes: sharing crash, localized charts, repeated Watch processing results, mobile-on-Mac launch. AES-GCM, expiry, persistent replay rejection and downgrade prevention support staged updates without re-pairing. Python handles only maintained connection/API adapters and lossless output; Swift/C# handle validation, display, hashes, timestamps and candidate selection. Readable sources/licenses are included. Older clients retain six core fields. This is beta software; report problems with dated diagnostics and reproduction steps.
