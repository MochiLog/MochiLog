# Documentation audience

Keep the root README user-facing: app features, downloads, requirements, setup, everyday use and support. Keep user prerequisites such as device trust and Developer Mode where they help setup.

Put implementation, build commands, signing/key management, CI, protocol details, verification results and development history in `docs/DEVELOPMENT.md` or specialized files under `docs/`. The root README may contain a clearly labeled link to developer documentation, but should not reproduce those instructions.

Preserve historical notes with their dates and versions. Do not present an old branch's release or verification status as current.
